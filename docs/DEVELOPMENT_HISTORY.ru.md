# Folder Tree Publisher — 0.7.0

Плагин Lightroom Classic для публикации обработанных фотографий на диск с сохранением структуры папок оригиналов. Самостоятельная реализация основной идеи [Jeffrey’s Folder Publisher](https://regex.info/blog/lightroom-goodies/folder-publisher); не копия его кода и не полная замена всех функций.

## Установка

1. Распакуйте `dist/FolderTreePublisher-0.7.0.zip` в постоянную папку. Или используйте готовую папку `FolderTreePublisher.lrplugin` из этого проекта.
2. В Lightroom Classic откройте **File → Plug-in Manager → Add** (Файл → Менеджер подключаемых модулей → Добавить).
3. Выберите папку **FolderTreePublisher.lrplugin**.
4. В модуле Library откройте панель **Publish Services** и нажмите **Set Up** рядом с **Folder Tree Publisher**.
5. Выберите заранее созданную отдельную **Папку публикации**. Исходные корни плагин получает из иерархии папок каталога Lightroom автоматически.
6. Настройте формат, качество, размеры, резкость, метаданные и водяной знак в штатных секциях Lightroom. Сохраните службу.
7. Перетащите фотографии в коллекцию **Фотографии** внутри службы и нажмите **Publish**.

Python, Lua и другие отдельные программы для работы плагина не нужны: используется встроенный Lua Lightroom.

## Пример

Верхняя папка в каталоге: `Фото` (на диске, например, `/Users/andrey/Pictures/Фото`)
Папка публикации: `/Экспорт`

| Оригинал | Результат с включённым ID |
| --- | --- |
| `/Users/andrey/Pictures/Фото/2026/Поездка/IMG_001.CR3` | `/Экспорт/Фото/2026/Поездка/IMG_001--123.jpg` |
| `/Users/andrey/Pictures/Фото/Семья/IMG_002.NEF` | `/Экспорт/Фото/Семья/IMG_002--456.jpg` |

ID — внутренний идентификатор фото в каталоге Lightroom. Опцию можно выключить для точных имён `IMG_001.jpg`. При совпадении имён разных фотографий публикация выдаст ошибку вместо перезаписи. Режим с ID подходит также для виртуальных копий и пар RAW/JPEG.

## Поведение

- Публикуются только добавленные в коллекцию фотографии. Папки не сканируются и фотографии не импортируются автоматически.
- Структура берётся из верхних папок каталога (`catalog:getFolders()`), включая название верхней папки, и расположения оригинала внутри неё. Внешние части пути вроде `/Users/andrey/Pictures` не переносятся. Снимки вне дерева каталога отклоняются. Корни считываются один раз в начале каждой публикации, независимо от набора выбранных фотографий.
- После редактирования фотографии используйте повторную публикацию. Если Lightroom не пометил файл после переноса оригинала, выберите **Mark to Republish** вручную.
- После успешной публикации по новому пути прежняя управляемая копия перемещается в корзину, если на неё больше не ссылается другая коллекция этой службы. Пустые папки остаются.
- Служебные файлы `.ftp-owner` больше не создаются. UUID фотографии и относительный путь хранятся в идентификаторе публикации Lightroom. Перезапись разрешена по пути, ранее записанному для этой фотографии в текущей или другой коллекции этой же службы; если такой записи нет, существующий файл вызывает ошибку.
- Не подменяйте опубликованные файлы посторонними файлами по тому же пути: принадлежность теперь определяется записью Lightroom, а не содержимым файла. Когда Lightroom забывает последнюю связь с оставленной на диске копией, повторное добавление фотографии не даёт права перезаписать этот файл автоматически.
- По умолчанию удаление из коллекции оставляет опубликованный файл на диске. Опция **При удалении из публикации перемещать копии в корзину** включает удаление через штатный цикл публикации Lightroom. Если корзина недоступна на сетевом томе, операция завершится ошибкой; безвозвратной заменой она не подменяется.
- Для каждой службы используйте собственную папку назначения. Не публикуйте одновременно из нескольких каталогов или служб в одно дерево.
- Папка назначения не должна совпадать с исходной верхней папкой публикуемого снимка или быть вложена в неё; обратная вложенность также запрещена. Назначение блокируется при редактировании существующей службы; для другого назначения создайте новую службу.
- Если несколько верхних папок каталога имеют одинаковые имена, публикация снимков из этих папок отклоняется. Покажите родительские папки в Lightroom, чтобы получить различимые верхние имена.
- При изменении верхних папок каталога путь при следующей публикации может измениться. Для переноса ранее опубликованных копий отметьте затронутые снимки **Mark to Republish**. Точное влияние команд показа/скрытия родительских папок на результат SDK ещё нужно проверить в Lightroom.
- Если диск назначения недоступен, плагин сообщает об ошибке и не создаёт заменяющую корневую папку.
- При ошибке замены файла плагин пытается вернуть прежний файл. Это не файловая транзакция: после отключения питания могут остаться `.ftp-new` / `.ftp-backup`; сохраните их для восстановления до повторной публикации.

## Границы версии 0.7

Это версия для проверки в Lightroom Classic. Доступны обычные и смарт-коллекции, а также вложенные наборы коллекций. Экспорт фотооригиналов с XMP, FTP/SFTP, перенос настроек Jeffrey’s Folder Publisher и режим выгрузки Smart Preview не реализованы. Сетевой ресурс должен быть подключён как обычный диск/папка.

Целевая среда — Lightroom Classic на macOS и Windows. Обработаны POSIX-пути, буквы дисков и UNC; пути macOS сопоставляются с учётом регистра. Работа интерфейса и реального экспорта внутри Lightroom, а также Windows и сетевые тома **ещё не проверены**. Поддержка конкретного релиза подтверждается после проверки в самом приложении.

## Проверка перед основной библиотекой

1. Создайте отдельную папку назначения и добавьте 2–3 фотографии из разных вложенных папок.
2. Опубликуйте, сравните пути и настройки изображений.
3. Измените обработку одного снимка и повторно опубликуйте: прежняя копия должна обновиться.
4. Проверьте виртуальную копию с включённым ID.
5. Уберите снимок из публикации и нажмите Publish: при выключенном удалении копия остаётся, при включённом — уходит в корзину.
6. Переместите оригинал внутри дерева папок каталога, вручную отметьте его для повторной публикации и проверьте новый путь.

## Автоматические проверки

`tests/test_plugin.py` запускает исходный Lua-код через Lua 5.1 из пакета Lupa. SDK Lightroom заменён тестовыми адаптерами файловой системы. Проверяются корни каталога, несколько исходных дисков, одинаковые имена корней, отсутствие снимка в дереве, вложенные пути, кириллица, Windows/UNC, выход за корень, коллизии, публикация и обновление, откат при отказе перемещения, перенос копии, удаление, сохранение копий, отсутствие новых sidecar-файлов, очистка старых `.ftp-owner`, отказ при несовпадении UUID, откат при сбое удаления прежней копии и отключённый том. Эти проверки не заменяют интеграционный тест в Lightroom.

```sh
python3 -m pip install lupa
python3 tests/test_plugin.py
```

Реализация использует [Lightroom Classic SDK](https://developer.adobe.com/lightroom-classic), включая [контракт Publish Service](https://lrc.mcor.dev/modules/SDK%20-%20Publish%20service%20provider.html).

## Обновление с 0.1.0

Замените папку плагина версией 0.3.0 и перезапустите Lightroom либо перезагрузите модуль в Plug-in Manager. Старое сохранённое поле `sourceRoot` больше не используется. Папка назначения и идентификаторы опубликованных фото совместимы.

При следующей публикации путь вычисляется по дереву каталога, включая имя верхней папки. Отметьте ранее опубликованные снимки **Mark to Republish**. После успешной записи по новому пути старая управляемая копия перемещается в корзину. Сначала проверьте обновление на нескольких фотографиях.

## Обновление с 0.2.0: отказ от .ftp-owner

Замените папку плагина версией 0.3.0 и перезапустите Lightroom. Новые публикации не создают `.ftp-owner`. Для очистки прежних служебных файлов отметьте уже опубликованные фотографии **Mark to Republish** и нажмите **Publish**.

При успешном обновлении или удалении опубликованной копии плагин убирает прежний `.ftp-owner`, только если его UUID совпадает с сохранённой записью Lightroom. Отсутствие такого файла не мешает повторной публикации. Служебные файлы для снимков, которые не были повторно опубликованы, остаются на месте; общего сканирования диска и массового удаления нет. Файлы с другим UUID не удаляются.

## Коллекции и смарт-коллекции (0.4.0)

После обновления плагина перезапустите Lightroom. В панели **Publish Services** нажмите правой кнопкой на свою службу **Folder Tree Publisher**:

- **Create Published Collection** — обычная коллекция; добавляйте снимки перетаскиванием.
- **Create Published Smart Collection** — смарт-коллекция; задайте правила Lightroom, например рейтинг не ниже четырёх звёзд или ключевое слово. Отбор выполняет Lightroom.
- **Create Published Collection Set** — набор для группировки коллекций, включая вложенные наборы.

Названия пунктов зависят от языка Lightroom. Существующая коллекция «Фотографии» сохраняется. Новые коллекции можно переименовывать, переносить в наборы и удалять. Для записи изменений на диск используйте **Publish**: автоматической фоновой публикации нет.

Все коллекции одной службы используют общие настройки экспорта и один корень назначения. Базовые пути строятся из **папок каталога**, а не из имён коллекций. Начиная с 0.5.0 каждая коллекция может отдельно преобразовать свой путь. Одна фотография в нескольких коллекциях использует одну опубликованную копию по одинаковому пути. Повторная публикация обновляет её; статусы остальных коллекций могут по-прежнему требовать публикации в Lightroom.

При включённом удалении копий файл уходит в корзину только тогда, когда на этот путь больше не ссылается другая коллекция службы. Это относится и к удалению целой коллекции/набора с удалением опубликованных файлов. Пока в другой коллекции остаётся запись публикации, в том числе ожидающая удаления, файл сохраняется. При выключенном удалении копии остаются на диске. Настройки и записи прежних версий совместимы; `.ftp-owner` не создаются.

Автотесты проверяют общую копию обычной и вложенной смарт-коллекции, коллизии разных фотографий, перенос пути, удаление последней ссылки, коллекции и набора, а также сохранение копий. Создание коллекций и применение правил в интерфейсе самого Lightroom ещё нужно проверить.

## Настройки пути коллекции (0.5.0)

В окне создания или редактирования обычной либо смарт-коллекции появился раздел **Путь публикации этой коллекции**. Настройки действуют только на эту коллекцию, не наследуются от наборов. По умолчанию сохраняется прежняя иерархия — обновление плагина само по себе не меняет пути.

| Настройка | Действие |
| --- | --- |
| Режим: сохранять иерархию | Использовать дерево папок каталога с преобразованиями ниже |
| Режим: всё в одну папку | Убрать всю исходную иерархию; поля числа уровней игнорируются |
| Подпапка перед иерархией | Например `Клиенты/Анна`; пусто — без добавления |
| Убрать уровней в начале | Удалить указанное число первых исходных папок, включая верхнюю папку каталога |
| Убрать уровней в конце | Удалить указанное число последних оставшихся исходных папок |
| Оставить первых уровней | Ограничить глубину оставшейся иерархии; 0 — без ограничения |
| Подпапка после иерархии | Например `JPEG`; добавляется после иерархии, перед именем файла |

Порядок преобразований фиксирован: убрать начало → убрать конец → ограничить глубину → добавить подпапки перед и после. Ограничение глубины не затрагивает добавленные подпапки. При удалении всех уровней остаётся имя файла. Вложенные подпапки можно разделять `/` или `\`; имена файлов не меняются.

Пример исходного пути: `Фото/2026/Поездка/IMG_001.jpg`.
Подпапка в начале `1111`, убрать в начале `1`, подпапка в конце `222` → `1111/2026/Поездка/222/IMG_001.jpg` внутри папки назначения службы.

Предпросмотр в диалоге обновляется при изменении полей и использует явно указанный условный пример, а не выбранную фотографию. Абсолютные пути, `..`, недопустимые имена подпапок и некорректные числа блокируют сохранение. Публикация повторно проверяет значения.

После сохранения настроек ранее опубликованные фотографии этой коллекции отмечаются для повторной публикации. Нажмите **Publish**, чтобы записать их по новым путям. Старые копии уходят в корзину только после успешной записи новых и при отсутствии ссылок из других коллекций. Файлы вне дерева назначения не затрагиваются. При совпадении имён разных фотографий плагин выдаёт ошибку; включите добавление ID в настройках службы для режима одной папки.

Одна фотография может иметь разные копии в разных коллекциях с разными путями. Если итоговые пути совпадают, используется общая копия. Для перехода к опубликованной коллекции по-прежнему показывается общий корень назначения службы.

Для установки замените папку плагина и перезапустите Lightroom. Проверены преобразования путей, ошибки ввода, независимые пути двух коллекций, перенос и удаление, отметка для повторной публикации. Вид диалога и работа SDK внутри Lightroom требуют проверки в приложении.

## Исправление 0.5.1

Отметка фотографий для повторной публикации после изменения настроек коллекции выполняется внутри `withWriteAccessDo`. Это исправляет ошибку `LrPublishedPhoto:setEditedFlagForRemotePhoto: must be called from within a withWriteAccessDo block`. Регрессионный тест требует полного доступа на запись и отклоняет private write access.

После замены плагина перезапустите Lightroom. Откройте настройки затронутой коллекции и проверьте сохранённые значения пути. Если снимки не отмечены для обновления после предыдущей ошибки, выберите **Mark to Republish**, затем **Publish**.

## Видео (0.6.0)

Поддерживается публикация фотографий и видео в одной службе, в обычных и смарт-коллекциях. Замените папку плагина и перезапустите Lightroom. Откройте настройки службы: в штатной секции **Видео / Video** включите **Include Video Files / Включать видеофайлы**, если флажок выключен, и выберите формат и качество. Плагин не принуждает включать этот флажок и не меняет ваши настройки экспорта.

Доступные форматы, включая Original и пресеты перекодирования, определяет установленная версия Lightroom. Кодирование выполняет Lightroom; плагин копирует результат с его фактическим расширением, например MOV или MP4. Неподдерживаемые Lightroom кодеки плагин не добавляет. Настройки JPEG/TIFF и других форматов фотографий не ограничивают видео.

Для видео действуют те же правила путей коллекции, ID в имени, повторной публикации и удаления, что и для фото. При смене выходного формата старая копия удаляется после успешной записи новой, если на неё не ссылается другая коллекция. При ошибке рендеринга старая копия сохраняется, а Lightroom получает сообщение об ошибке.

Автотесты проверяют передачу двоичных данных, расширения MP4/MOV, настройки пути и ID, повторную публикацию, ошибку кодировщика и удаление. В тестах используются искусственные данные, а не реальные видеоролики: кодирование и воспроизведение нужно проверить в Lightroom на коротком ролике.

## Русский и английский интерфейс (0.7.0)

Тексты настроек службы, коллекций, информации о плагине, подсказок, прогресса и собственных ошибок локализованы. Язык соответствует языку Lightroom: русский для русского интерфейса, английский для английского и языков без отдельного перевода. Отдельного переключателя языка в плагине нет.

Словари `TranslatedStrings_ru.txt` и `TranslatedStrings_en.txt` находятся рядом с `Info.lua`. Инструкция для независимых переводчиков — `TRANSLATING.md` в архиве. Для установки замените папку плагина и перезапустите Lightroom. Названия существующих коллекций, введённые пользователем подпапки и ранее опубликованные пути не меняются.

Проверены полнота словарей, подстановки, функциональные сценарии на обоих языках и английский fallback. Загрузка словарей и внешний вид интерфейса внутри Lightroom ещё требуют проверки.
